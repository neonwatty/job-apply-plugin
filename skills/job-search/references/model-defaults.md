# Search model defaults

When Agent Model Settings support is installed, the canonical profile stores optional durable defaults at `profile.agentModelPreferences`. Read the shared [task-key contract](../../answer-memory/references/agent-model-preferences.md) before changing a model choice:

```json
{
  "codex": { "search": "model-id", "searchReasoningEffort": "low", "application": "model-id" },
  "claudeCode": { "search": "model-id", "application": "model-id" }
}
```

Use only the `search` key for the current host (`codex` or `claudeCode`) and, on Codex, `searchReasoningEffort`. The `application` keys belong to Job Apply. Read these preferences on every search. They cannot change the active task's model or effort or grant browser access. An explicit model or effort choice for this request takes precedence and remains transient unless the owner asks to save it.

For browser-bound Codex desktop search, use the current top-level task's model and effort unless the owner explicitly asks for a separate task. Saved `codex.search` and `codex.searchReasoningEffort` values supply the pair for an owner-requested task; they do not themselves create one. Current-request choices override corresponding saved choices. Before creation, repeat the shared [Codex model preflight](../../answer-memory/references/agent-model-preferences.md#codex-model-preflight) for the top-level task tool. Resolve the local project through the host's project list, then create one local task with the selected `model` and `thinking` overrides; omit either when its host default is selected. Do not request a worktree for search. The launch prompt contains the requested sources and public filters, a direction to run this skill, and a direction to read private criteria from the canonical Store inside the new task. Exclude applicant values, resume paths, credentials, claim tokens, and browser state. The new task owns its visible browser, reads the Store itself, and does not create another task. Follow its progress through the host's task wait facility. Report the model and effort accepted by the launch tool; do not claim the child observed its runtime configuration unless it did. If creation or browser access fails, report the failure without silently replacing either choice or spawning a browser-bound subagent. Research in the current task is available only if the owner chooses its active model and effort.

Claude Code may use source research workers when its browser access and model override are available. Verify host support before launch. Codex source workers are permitted only when their own source access is verified; a model override alone is insufficient. An absent preference uses the host default at the chosen task or worker boundary. Do not guess an ID or silently substitute another model.

To read the default, use `node "<plugin-root>/apps/companion/command.mjs" store profile-inspect` after Answer Memory's root and QA-route checks. Read only `profile.agentModelPreferences` and the revision. Do not write this field when Agent Model Settings support is unavailable; report that the saved setting cannot be changed through the installed version. When support is available and the owner explicitly asks to save or clear a search default, inspect again immediately before the write and use a permission-restricted temporary JSON input with `profile-patch --input <path> --expected-revision <revision> --source user`. For a Codex search default, include only changed keys such as `{"agentModelPreferences":{"codex":{"search":"model-id","searchReasoningEffort":"low"}}}`; use `claudeCode` for that host or `null` for a requested clear. Remove the input on success or failure. Never replace the whole profile, the host object, or either `application` key. On revision conflict, reload and review the changed preference before retrying. Confirm the saved value from the returned inspection.
