- policy.mjs (existing): compose baseline fast/build/link suites with validated closures and existing matrix fallback. It may depend on focused-closure, matrix and patterns; no back-edge from graph primitives.
- run.mjs (existing): build graph from withSnapshot's actual tracked subject, validate selection before reuse or execution, include graph/selection identity in receipt key and validate mandatory results. It composes graph and policy; neither depends on runner.

## Discovery and fail-closed contract

Discovery evaluates the entire tracked JS/TS source/test candidate inventory of the tested snapshot, not merely files already listed by a static map. Enumerate every tracked repository path, including paths outside conventional source roots, with suffix .js, .jsx, .mjs, .cjs, .ts, .tsx, .mts or .cts. Include declaration files as type candidates. There is no path-prefix exclusion for tracked code; untracked dependencies and Git internals are outside the inventory. Normalize runtime/*.js to corresponding src/*.ts only with verified one-to-one correspondence; preserve both file identities in the digest. No glob silently authorizes a newly introduced production seam. Resolve the source and checked-in emitted graphs independently before comparing their normalized runtime closures; never substitute the source graph for emitted bytes.

Resolve static imports/reexports, literal require/import(), literal module URLs, and support-module chains. A module URL passed to a child process remains an edge even when there is no import statement. Type imports remain marked and participate in a distinct contract-change policy. Use AST parsing, not regex as the acceptance implementation. Relative literal file reads of the six frozen reference/schema/vector inputs use explicit reviewed data-edge declarations; a Python reference-only edit maps to its actual Node witness. Python production modules outside those declarations retain existing conservative fallback.

Do not pretend arbitrary JavaScript evaluation is solved. Missing literals, missing targets, unsupported relevant computed loading, ambiguous source/emission correspondence, parser failure, or evidence that the candidate scan is incomplete must disable focused permission and choose the existing conservative escalation. Dynamic imports confined to known external/builtin dependencies are classified explicitly. A new relevant consumer is re-discovered on the next snapshot and cannot inherit a passing historical declaration: require reviewed consumer coverage or escalate. Removing a target must not turn an include glob into zero tests.

The independent expected witness sets from the scout distinguish runtime from type-only reachability. Graph-derived closure and reviewed expected tests must agree; a missing expected edge or discovered unapproved consumer denies focused execution. This deliberate check may escalate new migration consumers until mappings are reviewed. It must not silently run the old smaller set. Errors in the graph analyzer are not a reason to grant a focused plan.

## Resolver and unsupported-call closure (normative refinement)

Read only tracked regular-file bytes from the immutable Git subject/tree. Reject tracked symlinks for candidate code, reference inputs and traversed local targets; do not follow them outside the snapshot. External relative/absolute targets escaping the repository disable focused permission. Builtin node: imports and fixed bare external package imports are terminal external edges only when resolved by the pinned lock/toolchain; a package or lock change retains global escalation. Unknown bare aliases, TS paths/baseUrl aliases and package-import aliases fail closed unless the existing pinned configuration supplies an exact resolver mapping independently exercised by fixtures. No arbitrary caller resolver.

Resolution follows explicit mode: emitted ESM .js paths resolve exactly as authored, with no invented extension/index fallback; source TypeScript .js specifiers may resolve to the pinned compiler's matching .ts/.tsx declaration/runtime source according to its actual module-resolution mode. CommonJS extension/index resolution follows a finite reviewed priority list (.js,.json,.node and index equivalents); external native/data targets are terminal only with declared package ownership. Ambiguous candidates or mismatched compiler resolution disable focus. For .mts/.cts, preserve .mjs/.cjs correspondence. Local JSON/data references are recorded where a six-seam declaration requires them; they do not become arbitrary executable edges.

Supported computed forms are bounded literal constants, literal new URL(specifier, import.meta.url), and local const aliases of those expressions. Follow these into import/require and Node child-process module arguments. No eval, environment-dependent path, template with dynamic substitution, arbitrary function interpretation or nonlocal alias propagation. A potentially repository-targeting unresolved import/require/Node child entry disables focused permission. This applies even outside the six seam roots, because it could be an unknown reverse consumer.

Avoid a perpetual-full implementation by reviewing actual unresolved callsites during P03.I and recording finite evidence-based terminal declarations for existing synthetic fixtures/external tooling. Each declaration binds exact path, AST call kind, exact normalized callsite text hash, containing-file content hash, classification and reason; no whole-file skip, suffix exemption or unchecked declaration accepted. A declaration may identify a builtin/external executable or code/module constructed inside a clearly owned disposable fixture. It may not hide a repository-source module or omit its known concrete URL. The containing-file hash is an invalidation boundary, never an exemption from scanning other calls. Recompute it from every subject before honoring the declaration. The independent coverage tests mutate declared callsite text/target and also change executable/script alias definitions while leaving spawnSync(executable,[script]) callsite text unchanged; all require invalidation. Relevant imported alias definitions remain unsupported unless their complete provenance is resolved, so a containing-file hash alone cannot authorize an imported mutable alias. Any undeclared or changed unresolved callsite remains fail-closed until reviewed; the accepted subject must demonstrate all six ordinary representative edits can receive their intended bounded tiers, proving the declarations did not simply force full selection forever.
