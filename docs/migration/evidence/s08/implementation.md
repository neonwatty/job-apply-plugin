## Proposed exact public inert API

point-value.ts exports:

- PythonPointJson = null | boolean | PythonText | NumericAtom | PythonPointJson[] | PythonObject<PythonPointJson>.
- PythonJsonDiagnosticProfile = '3.12' | '3.13' | '3.14'. These select the reviewed behavior for the captured versions above, not a claim of universal patch compatibility.
- PythonPointJsonOptions = { intMaxStrDigits: number; diagnosticProfile: PythonJsonDiagnosticProfile }.

point-parser.ts exports parsePythonPointJson(document: PythonText, options: PythonPointJsonOptions): PythonPointJson and parsePythonPointJsonBytes(bytes: Buffer, options: PythonPointJsonOptions): PythonPointJson. Both are synchronous. There is no implicit JS string conversion and no default diagnostic profile. The bytes entry validates options and Buffer identity, invokes the accepted decodePythonJsonBytes once, and passes its PythonText directly into the parser. It does not recode through UTF8 or JS strings.

Invalid rich options/profile or wrong input types fail deterministically before grammar/decoding: TypeError for wrong input/container/profile types or unknown profile; RangeError('intMaxStrDigits must be a nonnegative safe integer') for a supplied invalid numeric limit. A missing options object is TypeError. Validate options first, then input. Preserve the legacy entry's current options-first behavior and exceptions without imposing new runtime validation changes on it.

PythonPointJsonDecodeError extends Error, exported from point-parser.ts, with name 'JSONDecodeError'; readonly msg, doc: PythonText, pos, lineno, colno. doc retains the immutable exact input, not a normalized JS string. message is `${msg}: line ${lineno} column ${colno} (char ${pos})`. Coordinates count Python codepoints, LF increments line, and BOM/string-start/escape cursor distinctions are preserved. The error object remains extensible for later cause/context composition. Shared grammar emits facts; each facade projects its own diagnostic without maintaining duplicate grammar.

PythonPointJsonValueError extends Error, exported from point-parser.ts, with name 'ValueError'. Integer-limit failure maps the existing NumericAtomError only at the rich facade, with the exact observed Python message including configured limit and actual integer digits. Do not map arbitrary TypeError/RangeError/numeric syntax failures into it. Limits 0 and all nonnegative safe integers retain the accepted numeric primitive's semantics; 640/641 is the frozen Python comparison. CPython's interpreter-wide restriction on setting smaller nonzero limits is not being ported as a new parser option restriction.

point-serializer.ts exports serializePythonPointScope(value: PythonPointJson): string and PythonPointJsonCircularError extends Error, name 'ValueError', message 'Circular reference detected'. Output is compact, sorted, ensure-ASCII scope JSON using existing numeric formatting. Sort PythonText keys by codepoint values, not UTF16 or locale; duplicate content keys already obey S01 insertion identity. Iterative active-path tracking rejects array/object/mixed cycles while accepting shared acyclic containers. Unsupported runtime values receive TypeError at the rich adapter; no coercive toString/toJSON calls. Graph serialization errors remain extensible.

Existing parsePythonJson, PythonJson alias, Map output, NumericAtom shape, serializePythonScope and PythonJsonError identity/name/reason/offset/message remain unchanged. Store read wrappers must still catch instanceof PythonJsonError, while numeric-limit/configuration errors escape. Legacy cycles remain TypeError('Circular JSON value'). The new serializer's result is an ASCII JS string; it is not a claim that serialization/reload preserves literal-pair identity or key multiplicity.
