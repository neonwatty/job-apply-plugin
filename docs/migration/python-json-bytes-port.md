## Implementation boundary

Five TypeScript modules provide the explicit Buffer-to-PythonText boundary:

- `python-json-bytes.ts` validates Buffer ingress, snapshots the supplied view,
  detects Python's JSON byte encoding and dispatches to the selected codec.
- `python-byte-errors.ts` retains exact byte-decode error fields and an owned
  private byte snapshot. Every `object` access returns a new Buffer. Error objects
  remain extensible for caller context/cause composition; scalar fields are
  TypeScript readonly.
- `python-utf8-decode.ts` validates sequences and applies the narrow surrogatepass
  recovery while preserving the strict decoder's original error window.
- `python-utf16-decode.ts` combines complete encoded high/low pairs, retains lone
  units and reports odd tails at their actual offsets.
- `python-utf32-decode.ts` assembles unsigned values arithmetically, retains
  surrogate units independently and rejects out-of-range or truncated units.

Codec helpers return numeric point arrays; the entry constructs one PythonText.
No JavaScript string decoder, replacement character, UTF-16 string round trip,
Python subprocess, download or native adapter is used by production code.

`detectPythonJsonEncoding(Buffer)` returns the frozen codec labels.
`decodePythonJsonBytes(Buffer)` returns PythonText or throws the separately
exported PythonUnicodeDecodeError. Only Buffers are admitted at this internal
boundary; typed arrays, strings and coercible objects are rejected. This does not
narrow the legal byte values or claim complete Python bytes/bytearray API parity.
The decoder consumes only the provided Buffer view and does not mutate its input.

UTF-32 BOM detection precedes UTF-16 detection. Generic UTF-16/32 codec labels
occur only when the detector has identified their BOM; no implicit host byte order
is selected. UTF-8-SIG passes the BOM-free suffix to its UTF-8 decoder so errors
retain suffix bytes and offsets. UTF-16/32 failures retain the full original
BOM-containing byte object. Interior BOM points are preserved.

Complete UTF-8 encoded surrogates become literal surrogate codepoints. Incomplete
ED A0 remains the strict lead-byte continuation error; ordinary incomplete E2 82
retains its two-byte unexpected-end window. UTF-8 and UTF-32 do not merge adjacent
surrogate points; UTF-16 combines an encoded pair as CPython does. JSON backslash
escapes remain literal text for a later parser.

## Verification contract

`python_json_bytes_ts_support.mjs` contains a fixed textual copy of the independent
82-row expectations from the frozen reference test: 55 successes and 27 failures.
It imports neither that test module nor production code. The copied literal block
was compared back to the frozen source after accounting only for export keywords;
no expected outcome was generated by executing this implementation or a new oracle.
Root's independent review must retain the row-by-row binding.

The eight literal implementation test identities match the frozen audit. They
compare every ID, input byte sequence, detected codec, resulting codepoint array,
length, error type, encoding, object bytes, offsets, reason and full message.
Additional direct checks protect pair/scalar identity, unsigned assembly, empty
input, a 200,000-byte ASCII input, Buffer subviews, copied error bytes, caller
mutation, runtime input rejection and extensible error context. These are bounded
implementation checks, not additional differential Python reference claims.

The existing five reference tests and four PythonText tests remain read-only
required audit cells. All explicit Python 3.12/3.13/3.14 profiles must run without
skips for their acceptance; default Python may duplicate a profile.
