# Experimental host-browser workflow

The first host path uses the browser tools already exposed by Codex. The agent checks their capabilities, observes and operates the supplied controlled loopback fixture, and records value-free outcomes through the existing attempt broker. The plugin neither launches a restricted model runtime nor supplies a new browser tool. Other hosts need explicit capability and packaging validation before support claims.

The installed [host-browser skill reference](../../skills/job-apply/references/host-browser-workflow.md) defines the context/report commands and interruption loop. [Experimental workflow routing](../../skills/job-apply/references/experimental-workflow.md) supplies preparation, acquisition, recovery and approval boundaries. [Browser policy](../../skills/job-apply/references/browser.md) and [handoff policy](../../skills/job-apply/references/application.md) remain applicable.

`workflow attempt host-browser-context` returns canonical task/broker/guidance plus `hostBrowser`, whose `toolSource` is `host_existing`, evidence is `agent_attested`, and next step is `observe_and_act`, `inspect_and_handoff` or `resolve_workflow`. It supplies no selectors or browser observations. `workflow attempt host-browser-report` records only `progress` or `needs_info`; code rechecks exact revisions, current claim ownership, input scope and safe handoff rules. Acquisition and recovery remain existing attempt events.

Report results declare `persistenceScope: attempt_checkpoint` and `replayScope: report_recording_only`. Exact report retries cannot justify repeating browser effects. After an interrupted browser action, fresh DOM observation and canonical context determine remaining work. An unavailable observation stays uncertain; a guarded saved-session fingerprint can preserve a checkpoint for Needs Info without fabricating readiness.

Agent-attested reports are distinct from controlled adapter verification and independently captured host-tool evidence. Schema acceptance does not authenticate human presence or establish browser effects. Code-managed state does not physically constrain arbitrary host tools. Trusted-host rejection never authorizes a broker replacement or downgrade to attestation.

Scope remains explicit fictional Stores/native locks and controlled loopback pages. No owner Store/browser, live ATS, staging promotion or final submission is authorized. Acceptance must independently compare controlled-page state and write counts with canonical Store outcomes; deterministic protocol checks alone do not establish actual host-browser acceptance. Human UX scores and other-host support remain unverified until separately exercised.
